# NaïveProxy и Mieru

Naivka управляет официальными клиентами `klzgrad/naiveproxy` и `enfein/mieru`.
Компоненты устанавливаются и обновляются в «Настройки → О программе → Версии
компонентов». Архив проверяется по SHA-256 GitHub до замены файлов. Для обновления
работающего компонента нужно отключить VPN. Автоустановка рассчитана на современную
Windows x64, ARM64 и x86; Windows 7/8 не поддерживаются этими новыми компонентами.

После установки NaïveProxy обычные профили Naive используют официальный клиент.
Старые настройки, пароли и ссылки сохраняются. До установки компонента продолжает
работать прежний встроенный Naive. Профили с UDP-over-TCP остаются на sing-box:
официальный клиент этого расширения не предоставляет. При одинаковом SNI, но разных
адресах серверов запуск официального клиента отклоняется с объяснением, чтобы не
подменить адрес одного профиля адресом другого.

Для Mieru принимаются `mierus://`, стандартные protobuf-ссылки `mieru://` и JSON
с `profiles`. Сохраняются логин, пароль, адрес, пары порт/транспорт, диапазоны портов,
MTU, multiplexing и handshake. JSON поддерживается в подписке. Настройки локальных
слушателей и RPC из подписки не применяются. Расширения traffic-pattern, upstream
dialer и hashedPassword пока отклоняются: подключение с изменёнными параметрами
не выдаётся за поддержку исходного профиля. На один серверный endpoint создаётся
отдельный профиль; одновременно допускается до 32 профилей Mieru.

sing-box направляет трафик в локальные SOCKS-входы. Правила, статистика, автовыбор
и TUN остаются в sing-box. Процессы клиентов направляются напрямую, чтобы избежать
циклической маршрутизации. Пароли передаются через закрытые временные файлы,
а не аргументы процесса; файлы удаляются при остановке. При сбое клиента выполняется
ограниченное число перезапусков подключения. Неудачный запуск sing-box останавливает
и вспомогательные процессы.

## Свой VPS

В мастере установки можно дополнительно выбрать Mieru. Устанавливается официальный
`mita` v3.39.0 отдельной службой `naivka-mita`, с отдельным каталогом и конфигурацией.
Используются TCP и UDP 49997. При повторной установке пароль сохраняется. Изменённые
вручную порты и многопользовательская конфигурация не перезаписываются автоматически.
При ошибке запуска восстанавливаются прежние файлы и состояние службы. Уже
установленные sing-box/Caddy не откатываются при ошибке этого отдельного этапа.
Создание пользователя ОС и изменения UFW не входят в файловый откат.

Файрвол хостинга должен разрешать 49997 TCP/UDP; время на VPS должно быть синхронизировано.
На телефоне нужен клиент с поддержкой Mieru, например соответствующая версия Karing.
Функция «Друзья» не управляет пользователями mita в этом выпуске.

## Смена адреса VPS (Fornex)

[Инструкция Fornex](https://ru.fornex.com/help/change_ip/) относится к восстановлению
заказа из бэкапа с новым IP. Сначала через консоль хостинга нужно восстановить адрес,
маску, шлюз и при необходимости DNS в сетевой конфигурации ОС. Значения берутся из
панели именно этого VPS; примеры масок из статьи нельзя применять ко всем серверам.

Затем обновляются адрес SSH в Naivka, адреса серверов в ссылках и DNS A/AAAA домена.
При доменном имени Naive SNI остаётся доменным именем, его не следует заменять IP.
Старые QR-коды с числовым IP потребуется заменить. Эта операция не требует смены
VPN-протокола. Naivka не меняет сетевые интерфейсы VPS автоматически.

## Проверки

`NAIVE_CLIENT`, `MIERU_CLIENT`, `MITA_CLIENT` включают проверки официальных бинарников
в Go-тестах. Проверяются SOCKS handshake, повторный Sync, остановка и удаление
секретного файла; Mieru проверяется передачей HTTP через реальный mita по TCP и UDP
на loopback. Это не заменяет проверку Windows TUN и внешнего VPS/мобильного клиента.
