# Способы установки своего сервера

## Готовый VPN на sing-box

Мастер Naivka создаёт VLESS Reality и по выбору Hysteria2/NaiveProxy, затем добавляет готовые ссылки.
На VPS нужен Debian/Ubuntu и SSH с root или sudo без пароля.

Повторная установка сохраняет существующие ключи и версию sing-box. Ядро ниже 1.12.0 не принимается;
новая конфигурация дополнительно проверяется установленным ядром. Установщик не выполняет скрытое
обновление работающего бинарника.

Перед изменениями создаётся закрытый каталог вида `/etc/sing-box.backup.XXXXXXXX`.
Он содержит копии конфигурации/ключей и изменяемых служебных файлов. Не публикуйте его: там секреты.
При ошибке применения или локальной проверки скрипт восстанавливает сохранённые файлы и возвращает
службы sing-box/Caddy в прежнее состояние. Исходная служба не останавливается до проверки нового
конфига. Если резервную копию создать не удалось, применение не начинается.

Границы отката: установленные APT-пакеты, созданные системные пользователи, добавленные правила UFW
и настройки ядра ОС автоматически не удаляются. Внешний firewall хостинга скрипт не настраивает.
При аварийном выключении VPS или SIGKILL обработчик отката выполниться не может; сохранённая копия
нужна для ручного восстановления. Не запускайте одновременно сторонние средства редактирования
конфигурации. Установщик блокирует второй запуск собственного мастера для того же каталога.

`install-server.sh --remove` останавливает протоколы; это не восстановление конфигурации из копии.

Локальная самопроверка проверяет настоящий HTTPS-запрос через локальный клиент, но соединяется
с inbound по 127.0.0.1. Успешная проверка не доказывает доступность публичного порта с телефона.
Для проверки телефона сначала используйте полный VLESS Reality профиль, затем сравните Wi-Fi и
мобильную сеть, проверьте порт в панели хостинга и журнал Happ/Karing.

## Xray через 3X-UI

В мастере есть явный выбор «Xray через 3X-UI». Он отключает установку протоколов sing-box и выбирает
панель 3X-UI. После установки нужно создать VLESS Reality inbound в самой панели и импортировать
её ссылку. Установка панели не конвертирует прежние ссылки sing-box в Xray и не переносит пользователей.

Если на VPS уже работают sing-box или Caddy, новые inbounds Xray должны использовать свободные порты.
Не включайте одновременно разные серверные ядра на одном IP/порту. При замене транспорта/ядра нужны
проверка клиента и отдельный план миграции; новая панель сама по себе не исправляет блокировки сети.

Официальный самостоятельный способ Xray: https://github.com/XTLS/Xray-install . Он поддерживает
установку конкретной версии через `--version`; в Naivka отдельный автоматический Xray-установщик
без панели пока не реализован.

## Remnawave — план отдельной интеграции

Remnawave пока не добавлен в автоматический установщик Naivka. Его нельзя корректно включить только
новым пунктом списка панелей: нужны Docker Compose, панель, база данных, HTTPS и Node с Xray.
Текущий скрипт «Друзья» редактирует sing-box; для Remnawave нужен адаптер API пользователей/подписок.

Перед реализацией режима нужны ответы:
- Какие домены используются для HTTPS панели и подписки?
- Панель и Node будут на одном VPS или раздельно?
- Какие порты/сервисы уже заняты на этих VPS?

Официально возможно размещение на одном VPS, но рекомендуется разделение панели и узла.
Панели нужно минимум 2 GB RAM / 2 CPU / 20 GB диска (рекомендовано 4 GB / 4 CPU), узлу — минимум
1 GB RAM / 1 CPU. Применение схемы на одном VPS требует общей оценки ресурсов и портов.

Первый релиз интеграции должен закреплять проверенные версии компонентов, генерировать секреты,
проверять DNS/HTTPS/health, создавать профиль и тестового пользователя, проверять трафик через
экспортированную ссылку, сохранять возможность восстановления. Не должно быть автоматического
удаления sing-box/Caddy и молчаливой миграции существующих пользователей.
