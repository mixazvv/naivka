# Смена IP VPS

Откройте **Свой сервер → Сменить IP** у нужного VPS либо ту же кнопку в
**Управлении VPS**. Введите IPv4/IPv6 из панели хостинга и нажмите «Проверить новый адрес».
Мастер делает публичную проверку SSH по сохранённому порту без отправки пароля.
Ключ должен совпасть с сохранённым ключом VPS. Несовпадение не обходится галочкой:
сверьте ключ в консоли хостинга и добавьте сервер заново, если это новая установка.

Мастер покажет прежний/новый IP и связанные подключения. Можно снять галочки с VPN,
которые не нужно переносить. При сохранении VPN должен быть отключён. Обновляются:

- адрес записи своего VPS;
- выбранные VPN-подключения с прежним числовым IP;
- SSH-адреса панелей с тем же пользователем, портом и подтверждённым ключом;
- числовой адрес в публичном URL такой панели, если он совпадал с прежним IP.

SNI, пароли, ключи Reality, отпечатки сертификатов, порты, идентификаторы и избранное
сохраняются. Доменным VPN-профилям нужно обновить DNS A/AAAA, а серверам из подписок —
источник подписки. Старые QR-коды с IP нужно выдать заново. Для доменного HTTPS панели
сохраните домен и обновите DNS; сертификат на числовой IP сам не меняется.

Перед записью создаётся каталог `address-backup-*` в папке данных Naivka с прежним
`settings.json`, защищённым тем же способом, что основной файл. Для ручного возврата
полностью закройте Naivka и восстановите этот файл в её папке данных. Возврат заменит
все настройки состоянием резервной копии. Повторно выданные после миграции ссылки
будут содержать актуальный адрес.

Если настройки изменились между проверкой и сохранением, повторите проверку.
При ошибке записи прежние настройки в памяти сохраняются. Сеансы друзей и туннели
перенесённых панелей закрываются: следующий вход пойдёт по новому адресу.

## Когда SSH недоступен

[Инструкция Fornex](https://ru.fornex.com/help/change_ip/) относится к восстановлению
VPS из бэкапа с другим IP. Если Linux хранит прежний адрес и шлюз, сначала восстановите
сеть через консоль в панели Fornex. Адрес, префикс сети и шлюз берутся из панели
именно вашего VPS; примеры масок из статьи нельзя применять к любому серверу.

Посмотрите `ip -br addr` и `ip route`, определите используемый сетевой менеджер и
обновите его конфигурацию по инструкции хостинга. Для netplan сначала используйте
`netplan try`, оставаясь в консоли, чтобы при потере доступа был автоматический возврат.
После восстановления SSH вернитесь в мастер.

Naivka не получает новый IP у провайдера, не меняет интерфейсы/маршруты Linux и
не редактирует DNS в кабинете хостинга. Проверка SSH не подтверждает работу VPN,
файрвола или сертификата: после сохранения подключитесь и проверьте интернет.
